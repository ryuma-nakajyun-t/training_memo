
# DECIMAL
GIS用途なら、DECIMALを推奨します。

違いを簡単に言うと、
型	特徴DECIMAL	正確な値を保存
DOUBLE	近似値を保存

例:
```text
43.064444
```
を保存すると、
```sql
DECIMAL(9,6)
```
なら
```text
43.064444
```
がそのまま保持されます。  

一方、  
DOUBLE  
は内部的には2進数で保持するため、  
```text
43.06444400000001 
``` 
のような誤差が発生する可能性があります。  

GISでの使い分け  
マスタデータ  
住所マスタや施設マスタなど  
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
が多いです。

理由は、  
- 入力値をそのまま保持したい  
- データ連携時に誤差を出したくない  
ためです。  

GISエンジン  
PostGISなどのGISエンジン内部では
DOUBLE PRECISION
を使うことがあります。

理由は、
- 距離計算
- 面積計算
- 座標変換  
などの計算速度が速いためです。

### Javaとの関係
Javaなら
BigDecimal
⇔
DECIMAL
double
⇔
DOUBLE
が対応します。

### 実務のおすすめ  
施設マスタや住所マスタなら
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
で十分です。

緯度の最大値は ±90、経度は ±180 なので、
```sql
DECIMAL(10,7)
```
なら
```text
90.1234567
180.1234567
```
まで保存でき、  
約1cm精度になります。

「都道府県コードを0埋めしてDBに保持する」話と同じで、  
マスタデータは計算のしやすさよりも値を正確に保持することを優先するのが基本です。  
その観点では GIS の座標も DECIMAL のほうが設計意図が明確です。
