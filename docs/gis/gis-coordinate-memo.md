# GISで扱う座標
GISで扱う座標は、  
「元データの精度」  
と  
「DBで保持する桁数」  
を分けて考えると整理しやすいです。  

小数点桁数と精度    
緯度経度を10進数で表現した場合    
| 小数点以下 | 精度の目安 |  
| -----------| -----------|   
| 1桁 | 約11km | 
| 2桁 | 約1.1km | 
| 3桁 | 約111m | 
| 4桁 | 約11m | 
| 5桁 | 約1.1m | 
| 6桁 | 約11cm | 
| 7桁 | 約1.1cm | 

例  
```text
43.0644444
```
を丸めると  
| 座標 | 精度 | 
| ---- | ---- | 
| 43.0644444 |  元データ | 
| 43.064444   | 小数点6桁 | 
| 43.06444   |  小数点5桁 | 
| 43.0644    |  小数点4桁 | 
になります。  

丸め方  
一般的には四捨五入です。  

Java  
```java
BigDecimal lat = BigDecimal.valueOf(43.0644444);
lat = lat.setScale(6, RoundingMode.HALF_UP);
System.out.println(lat);
```
結果  
```text
43.064444
```

例えば  
```text
43.0644446  
```
なら  
```text
43.064445 
``` 
になります。  

DB設計の考え方  
施設マスタ  
施設の位置を示すだけなら  
```sql
DECIMAL(9,6)
```
十分です。  

例
```sql
latitude  DECIMAL(9,6)
longitude DECIMAL(10,6)
```

精度  
```text
約11cm  
住所マスタ  
住所ジオコーディングも  
DECIMAL(9,6)  
```
が多いです。  

建物単位で十分な精度があります。  
GPSログ  
移動履歴や測位データなら  
DECIMAL(10,7)  
または  
DOUBLE  
が使われます。  

## 実務でよく見る保持方針
### パターン1
```text
元データ  
43.0644447  
DB  
43.064445  
(小数点6桁で四捨五入)  
```

### パターン2  
```text
元データをそのまま保持  
DECIMAL(10,7)  
43.0644447  
そのまま保存  
画面表示だけ  
43.064445  
へ丸める。  
```

個人的におすすめ  
マスタデータなら  
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
で保持し、  

表示時だけ
```java
setScale(6, RoundingMode.HALF_UP)
```
で6桁にする設計です。  

理由は、  
- 元データを失わない  
- 将来精度要件が上がっても再取り込み不要  
- 表示の見やすさは別制御できる  
からです。  

システム設計書に書くなら、  
緯度経度は10進数形式で保持し、  

DBは DECIMAL(10,7) を使用する。  
表示時は小数点以下6桁へ四捨五入する。  
という記載だと実務的に自然です。
