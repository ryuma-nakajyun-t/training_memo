# 小数点の桁数
GISでマスタデータとして保持する緯度経度の桁数は、  
用途によりますが 小数点以下6〜7桁が一般的 です。  

小数点以下桁数	誤差の目安
```text
3桁	約111m
4桁	約11m
5桁	約1.1m
6桁	約11cm
7桁	約1.1cm
8桁	約1mm
```
例えば東京駅は
```text
35.681236
139.767125
```
のように小数点以下6桁程度で表現できます。

実務では次のような傾向があります。
```text
地図表示のみ → 5〜6桁
住所・施設マスタ → 6桁
GPS測位データ → 6〜7桁
測量・基準点 → 7桁以上
```

ただし、GPS自体の精度が数m程度であることが多いため、業務システムのマスタでは
```sql
DECIMAL(9,6)
```
または
```sql
DECIMAL(10,7)
```
で保持することがよくあります。

自治体や企業の施設マスタ、店舗マスタであれば   
小数点以下6桁（約11cm精度）を採用するのが無難 です。  
桁数を増やしても元データの精度以上にはならず、  
比較処理やデータ量だけが増えるためです。  

DBに保存する場合は、
通常は**10進数（Decimal Degrees, DD）**で  
保存します。  
例えば、
```text
43°03′52″ → 60進数表記
43.064444 → 10進数表記
```
です。

先日聞いていた座標
```text
43°03′52″
```
を10進数へ変換すると、
```text
43 + 3/60 + 52/3600
= 43.064444...
```
になります。  

GISや地図APIではほぼ10進数が使われています。  
例:
```text
latitude  = 43.064444
longitude = 141.346944
```
**Google Maps**、**OpenStreetMap**、**PostGIS**なども基本的に10進数です。

DB定義例:
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
または
```sql
latitude  DOUBLE
longitude DOUBLE
```

実務では
```text
入力時: 60進数でも可
DB保存: 10進数
画面表示: 必要に応じて60進数へ変換
```
という構成が一般的です。

理由は、  
- 距離計算
- 範囲検索
- GIS処理  
が10進数の方が圧倒的に扱いやすいためです。
60進数のままDBに持つことはほとんどありません。
