# 超正確な時刻が必要な場合
超正確な時刻が必要な場合は、用途によって方法が変わります。

### ① 一般的なログ
```bash
date '+%Y-%m-%d %H:%M:%S.%3N'
```
ミリ秒で十分です。
例:
```text
2026-10-27 12:34:56.123
```

### ② 性能測定
date よりも time やアプリケーションの高精度タイマーを使います。

Javaなら
```java
System.nanoTime()
```

Pythonなら
```python
time.perf_counter_ns()
```
これらは処理時間測定向けです。

### ③ サーバ間で時刻を厳密同期
NTP
```bash
chronyd
ntpd
```
で通常はミリ秒～数十ミリ秒程度に同期します。

### ④ 金融取引・通信機器・研究用途
PTP (Precision Time Protocol)を使用します。  
```text
GPS
 ↓
PTP Grandmaster
 ↓
各サーバ
```
構成にすると  
マイクロ秒、環境によってはサブマイクロ秒レベルまで同期可能です。  

### ⑤ Linuxで現在取得できる精度確認
```text
clock_gettime()
```
を使うプログラムが最も一般的です。  

date は内部的にも CLOCK_REALTIME から時刻を取得していますが、  
```bash
date '+%N'
```
の  
```text
123456789
```  
が本当にナノ秒精度で正しいとは限りません。  

実務で多い使い分け  
|  用途| 方法 | 
| --- | --- | 
| アプリログ | %3N |  
| SQL性能測定| %6N | 
| Java処理時間測定| System.nanoTime() | 
| サーバ時刻同期 | NTP | 
| 超高精度同期 | PTP + GPS | 

インフラや業務システムでは、  
あなたが最近勉強している   
PostgreSQL や Spring Boot のチューニング程度なら ミリ秒（%3N）で十分 なことがほとんどです。  

ナノ秒が本当に必要になるのは、  
金融取引システムやネットワーク機器開発など特殊な分野です。
