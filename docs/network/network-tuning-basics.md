# ネットワークチューニングの理解に必要な基礎
この手の「ネットワークチューニング」を本当に理解するには、  
**シェル**そのものよりも、
その**下にある仕組み**を理解する方が大切です。

一言で、**チューニング**を表現するなら、
```text
システムの無駄を減らし、効率を高めるための最適化。
```
といえる。

### 項目一覧
- 1. Linuxのプロセス
- 2. 標準入力・標準出力・パイプ
- 3. ファイルシステム
- 4. TCP/IPの基礎
- 5. SSHの仕組み
- 6. rsyncの仕組み
- 7. 性能測定

おすすめの順番は次のとおりです。  
### 1. Linuxのプロセス
---
まず最優先です。  
例えば、
```bash
grep ERROR file.txt
```
を実行すると、
```text
シェルがgrepを起動
OSがプロセスを作成
grepが実行
grepが終了
```
という流れになります。

なぜ
```bash
cat file.txt | grep ERROR
```
より
```bash
grep ERROR file.txt
```
が速いのかは、
プロセス作成コスト  
を理解すると納得できます。  

### 2. 標準入力・標準出力・パイプ
---
```bash
cat file.txt | grep ERROR
```
の **|** が  
何をしているかを理解します。

実行してること
- 標準入力(stdin)
- 標準出力(stdout)
- 標準エラー(stderr)
です。
シェルスクリプトを読む力が大きく向上します。

### 3. ファイルシステム
---
例えば
```bash
find
ls
stat
```
が何をしているか。

なぜ
```bash
find /
```
が重いのか。

これは  
```text
ディレクトリ
inode
メタデータ
タイムスタンプ
```
を知ると理解できます。

### 4. TCP/IPの基礎
---
ネットワークチューニングなら必須です。  
最低限、  
- IPアドレス-
- ポート番号
- TCP
- DNS
を理解します。  

例えば  
```bash
ssh server
```
は実際には
- DNS問い合わせ
- TCP接続
- SSH認証
- コマンド実行
をしています。

なぜ、  
SSH接続を何回もすると遅いのかが分かります。

### 5. SSHの仕組み
---
あなたは  
- Git
- rsync
- Ansible
を触っているので重要です。

実は
```bash
git push
```
も
```bash
rsync
```
も
```bash
ansible
```
も 
SSH を使うことが多いです。  

理解すると  
- 接続回数削減
- ControlMaster
- 多重化
などの意味が見えてきます。

### 6. rsyncの仕組み
---
例えば
```bash
scp
```
は全量コピーですが、
```bash
rsync
```
は
- サイズ比較-
- タイムスタンプ比較
- チェックサム比較
を行います。

つまり  
「変更がなければ転送しない」  
という考え方です。  

以前の質問した  
「コンパイルが必要かを先に調べる」  
と全く同じ思想です。  

### 7. 性能測定
---
最後にこれです。
- time
- top
- vmstat
- iostat
など。

実務では  
**遅い気がする**  
ではなく  
どこが何秒かかっているか
を測定して**原因を特定**します。  

あなたの場合、  
学習順は  
- Linuxプロセス
- 標準入力・出力
- TCP/IP基礎
- SSH
- rsync
- 性能測定
- Ansible
が自然だと思います。

実際、あなたが最近学習している  
- Linux
- Shell Script
- Git
- SSH
- rsync
- Ansible
はすべてつながっています。  

「処理を実行する」「接続する」「転送する」「差分だけ送る」  
という一連の流れとして理解すると、  
個別のコマンド暗記ではなく構造で理解できるようになります。
