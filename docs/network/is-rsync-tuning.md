# rsyncはチューニングに含まれる？
rsyncを使った改善は広い意味ではチューニングに含まれます。  
ただし、実務では少し整理して考えると分かりやすいです。  

### ① システムチューニング
OS設定やカーネルパラメータを変更するものです。  
例
```bash
sysctl
```
でTCPバッファを変更する。  
これは  
「環境を速くする」チューニングです。

### ② アプリケーションチューニング
プログラムやシェルスクリプトの処理を改善するものです。  
例  
```bash
cat file | grep ERROR
```
↓
```bash
grep ERROR file
```
無駄なプロセスを減らします。

### ③ 処理方式のチューニング
rsyncはこちらに近いです。  
例えば  
```bash
scp file server:
```
は毎回全量転送です。  

一方
```bash
rsync -av src/ server:/data/
```
は差分だけ転送します。

これは  
転送方法そのものを見直して速くする  
という考え方です。  

あなたが以前話していた
例でいうと
```bash
javac ...
```
を毎回実行する
↓
変更がある場合だけコンパイルする  
これも同じです。  

CPUを速くしたわけではありません。  
アルゴリズムや処理方式を変えて、
「そもそも無駄な処理をしない」  
ようにしています。

実務ではむしろ
- rsyncで差分転送
- SSH接続回数削減
- コンパイル不要判定
- 不要なDBアクセス削減
のような  
**無駄な処理をなくすチューニング**  
の方が効果が大きいことが多いです。  

あなたが興味を持っている  
「変更がなければコンパイルしない」という考え方は、  
rsyncの差分転送と本質的に同じで、  
「変わったものだけ処理する」  
というチューニングの基本原則そのものです。
