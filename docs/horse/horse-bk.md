# 競馬の歴史
競馬の歴史を一言でいうと、  
**馬の能力を競う行事が、軍馬育成と娯楽を経て、公営ギャンブルへ発展した歴史**です。  

### ① 古代～江戸時代
日本では古くから馬が重要な戦力でした。
```text
神事としての「競馬（くらべうま）」
武士の馬術訓練
流鏑馬（やぶさめ）
```
などが行われていました。  
ただし、現在のような楕円形コースを走る競馬ではありません。  

### ② 近代競馬の誕生（1860年代）
現在の競馬の原型は、横浜の外国人居留地で行われた西洋式競馬です。
```text
1860年ごろ 横浜で洋式競馬開催
1862年 日本初の洋式競馬場が誕生
1866年 横浜競馬場（根岸競馬場）が整備
```
ここが日本近代競馬の出発点とされています。

### ③ 競馬法と公認競馬（1900～1930年代）
日清戦争・日露戦争を経て、
```text
「強い軍馬を育てるには馬の改良が必要」
```
という考えから競馬が奨励されました。

その後、
```text
1905年 馬券発売が認められる
1923年 競馬法制定
各地の競馬倶楽部が設立
```
という流れになります。

### ④ 日本ダービー誕生（1932年）
競馬ファンなら有名な
```text
東京優駿（日本ダービー）
```
が1932年に創設されました。
現在でも最も権威あるレースの一つです。

### ⑤ 戦後の国営競馬
第二次世界大戦後、
```text
日本競馬会が解散
国営競馬へ移行
```
しました。

### ⑥ JRA誕生（1954年）
1954年、
```text
日本中央競馬会（JRA）
```
が設立されます。

この時から現在の中央競馬の仕組みが始まりました。   
主な競馬場は
```text
東京
中山
京都
阪神
中京
```
など現在とほぼ同じです。

### ⑦ 国際化（1980年代以降）
1981年、   
```text
ジャパンカップ
```
創設。
世界の強豪馬を日本へ招待するレースで、
日本競馬の国際化が大きく進みました。

### ⑧ 世界トップレベルへ
1990年代以降、
```text
オグリキャップ
ディープインパクト
オルフェーヴル
アーモンドアイ
イクイノックス
```
などの名馬が登場し、  
日本競馬は**世界最高水準の競馬賞金と競走レベル**を持つまでに成長しました。  

歴史の流れ（超要約）  
```text
神事・武士の競馬
    ↓
横浜で洋式競馬（1860年代）
    ↓
競馬法制定
    ↓
日本ダービー創設（1932）
    ↓
国営競馬
    ↓
JRA発足（1954）
    ↓
ジャパンカップ（1981）
    ↓
世界トップクラスの競馬大国へ
```

面白いのは、現在の競馬場25場のうち、  
東京・中山・京都・阪神などの中心競馬場のルーツは**100年以上前**までさかのぼることです。  

競馬場の位置データをGISで見ると、  
明治時代から続く競馬文化の痕跡が今でも残っています。  


# 公営ギャンブル　とは
公営ギャンブルとは、  
国や地方自治体などの公共団体が法律に基づいて運営するギャンブルです。  

日本では賭博（ギャンブル）は原則禁止ですが、  
法律で特別に認められたものだけが公営ギャンブルとして実施されています。  

代表的なものは次の5種類です。
| 種類 | 主催 | 
| ---- | ---- | 
| 競馬  | JRA・地方自治体 | 
| 競輪 | 地方自治体 | 
| ボートレース（競艇） | 地方自治体 | 
| オートレース | 地方自治体 | 
| スポーツ振興くじ（toto） | 日本スポーツ振興センター | 

競馬なら、  
```text
馬券を購入
的中すると払戻金を受け取る
売上の一部は賞金や運営費になる
残りは自治体収入や社会還元に使われる
```
という仕組みです。

構造としては、
```text
利用者
 ↓
投票（馬券購入）
 ↓
売上
 ├─ 払戻金
 ├─ 運営費
 ├─ 賞金
 └─ 自治体収入
```
です。

例えば  
地方競馬や競輪、ボートレースでは、
収益が自治体の財源となり、  
公共サービスの原資として活用されることがあります。  

歴史的には、
```text
賭博は禁止
 ↓
財源確保のため例外的に認可
 ↓
公営競技として制度化
 ↓
現在の競馬・競輪・競艇・オートレース
```
という流れで発展しました。

面白い点として、  
競馬場は全国25場しかありませんが、  
競輪場は40場超、  
ボートレース場は24場あり、    
公営ギャンブルごとに施設の分布がかなり違います。  

GISで分析すると、  
競馬は広大な土地が必要なため都市周辺に点在し、  
競輪やボートレースは比較的設置しやすい傾向が見えてきます。  






# 競馬場の施設設備
競馬場は単にレースをする場所ではなく、  
「馬の生活・調教・競走・観客サービス」を支える巨大施設です。  

主な設備を整理すると、  
### ① コース
レースを行う場所です。
```text
芝コース
ダートコース
障害コース（一部競馬場）
直線走路
```
例：
```text
東京競馬場：芝・ダート・障害
中山競馬場：芝・ダート・障害
新潟競馬場：日本最長級の直線コース
```

### ② パドック
レース前に馬を周回させる場所です。
観客は
```text
馬体
歩き方
気配
発汗状況
```
などを確認します。

### ③ 厩舎（きゅうしゃ）
馬の住居です。  
設備例  
```text
馬房
飼料庫
洗い場
装蹄スペース
```
ただしJRAでは多くの競走馬は  
```text
美浦トレーニングセンター
栗東トレーニングセンター
```
に所属しており、開催時に競馬場へ輸送されます。  

### ④ 検量室
騎手や関係者の管理施設です。  
ここで  
```text
騎手の体重測定
装備確認
レース後の審議
```
などが行われます。  

### ⑤ 発走設備
レース開始のための設備です。  
```text
ゲート（発馬機）
スタート地点
判定装置
```

### ⑥ 写真判定設備
ゴール順を判定します。  
```text
高速カメラ
写真判定システム
着差測定装置
```
僅か数センチの差も判定できます。

### ⑦ 馬診療施設
競走馬専用の医療設備です。  
```text
診察室
レントゲン
超音波検査
救護馬運搬車
```
人間の病院に近い設備があります。  

### ⑧ 馬場管理設備
コースを維持する設備です。  
```text
芝刈り機
散水設備
排水設備
整地車両
```
競馬場では毎日のように馬場整備が行われます。  

### ⑨ 観客施設
一般来場者向けです。  
```text
スタンド
指定席
フードコート
ファミリーエリア
イベント広場
```
東京競馬場などは競馬以外の日でも公園のような規模です。  

### ⑩ 馬券発売設備
現在はネット投票が主流ですが、  
```text
発券機
払戻機
キャッシュレス端末
```
も設置されています。  

### ⑪ 放送・情報システム
競馬場全体を支えるIT設備です。  
```text
オッズ計算
馬券発売システム
映像中継
着順判定
大型ビジョン
```
近年は巨大なデータセンター並みのシステムで運用されています。

構造としては、  
```text
競馬場
├─ レース施設
│   ├─ コース
│   ├─ ゲート
│   └─ 写真判定
├─ 馬関連施設
│   ├─ パドック
│   ├─ 厩舎
│   └─ 診療施設
├─ 運営施設
│   ├─ 検量室
│   ├─ 審判室
│   └─ ITシステム
└─ 観客施設
    ├─ スタンド
    ├─ 飲食店
    └─ 馬券売場
```

GISで見ると競馬場は「スポーツ施設」というより、  
小さな町ひとつ分の機能を持った複合施設に近い存在です。  

東京競馬場や中山競馬場クラスになると、  
スタンド、厩舎地区、馬場、駐車場を含めて非常に広大な敷地になります。

# 競馬場の配信システム
競馬場の配信システムは、単なる映像配信ではなく、  
```text
「レース映像・実況・オッズ・馬券発売・着順判定をリアルタイムに全国へ配信する巨大システム」  
```
です。

構造としては、
```text
競走馬
 ↓
競馬場
 ↓
映像・音声取得
 ↓
中央システム
 ↓
全国配信
 ├─ 競馬場
 ├─ WINS
 ├─ J-PLACE
 ├─ テレビ局
 ├─ インターネット
 └─ スマホアプリ

映像配信
```

競馬場には多数のカメラがあります。
```text
スタート地点
向正面
第3・第4コーナー
ゴール前
パドック
ウイナーズサークル
```
などを撮影し、テレビ中継やネット配信へ送ります。

オッズ配信

馬券が購入されるたびに、

馬券購入
 ↓
中央サーバ
 ↓
オッズ再計算
 ↓
全国配信


が繰り返されます。

そのためレース直前は秒単位でオッズが変化します。

発売システム

JRA-VANや即PATなどを含め、

競馬場
WINS
インターネット投票

の購入情報を集約しています。

大量アクセスが発生するため、高い可用性が求められます。

着順判定システム

ゴール前では

高速カメラ

# jra とは
JRAとは、**日本中央競馬会（Japan Racing Association）**の略称です。  
中央競馬を運営する特殊法人で、農林水産大臣の監督下に置かれています。  
1954年9月16日に設立されました。  

簡単にいうと、  
```text
JRA = 日本の「中央競馬」を運営する組織
```
です。

主な役割は、

馬事・畜産振興など

JRAの中央競馬には、東京・中山・京都・阪神など全国10の競馬場があります。

日本の競馬

# リアルタイム更新処理　とは​‌

# これ何が難しいの？
率直に言うと、  
「画面を作ること」自体はそれほど難しくないです。  

難しいのは画面の裏側です。  
例えばオッズ一覧画面なら、  
```text
馬番
馬名
単勝オッズ
人気順位
```
を表示するだけなら、
```sql
SELECT * FROM odds
```
してThymeleafで表示するだけです。  
これは一般的な業務システムと同じです。

この案件で難しくなりそうなのは、  

### ① リアルタイム更新
普通の業務システム
```text
検索
↓
結果表示
↓
終わり
```

オッズ画面
```text
表示中
↓
5秒後更新
↓
10秒後更新
↓
15秒後更新
```
発走直前は数秒ごとに変化します。  
つまり  
- WebSocket
- ポーリング
- 非同期通信
が関係します。

### ② 時間による自動切替
例えば
```text
09:00 ニュース
09:30 CM
09:35 オッズ
09:40 レース映像
```

なら
利用者がボタンを押さなくても
```text
時刻到達
↓
自動切替
```
しなければなりません。
ここは業務システムより制御システム寄りです。

### ③ 障害時の復旧
例えば
```text
オッズ配信停止
```
したら、
```text
再接続
再取得
復旧
```
が必要です。
顧客管理システムなら多少遅れてもよいですが、
競馬場の大型モニタは止まると困ります。

### ④ 状態管理
これが意外と難しい。
例えば
```text
発売前
↓
発売中
↓
締切
↓
確定
```
状態によって画面表示が変わります。

プログラムでは
```java
enum RaceStatus {
    BEFORE,
    OPEN,
    CLOSED,
    FIXED
}
```
みたいな設計になります。
業務システム経験者でも苦戦しやすい部分です。

### ⑤ 監視画面
案件説明に  
- 運用監視
- メディアサーバ
がある場合、  
画面は作れるが  
- どのサーバが落ちたか
- どのコンテンツを再生中か
- どの配信先が異常か  
を管理するロジックが難しいです。

逆にあなたの場合、  
最近学習している  
- Spring Boot
- MVC
- PostgreSQL
- SQL
- CSV取込
- ファイル移動
- Linux
はかなり近いです。

足りない可能性が高いのは  
- WebSocket
- Scheduler
- 非同期処理
- 状態遷移設計
です。

なので、  
「画面項目が難しい案件」ではなく、「リアルタイム性と状態管理が難しい案件」  
だと思った方が実態に近いですね。

むしろ画面そのものは、  
```text
検索
一覧
登録
編集
削除
監視
```
という業務システムでよく見る構成になる可能性が高いです。
